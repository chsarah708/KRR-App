# KRR App Deployment Guide for Render

This guide will help you deploy your KRR (AI Literature Review System) application on Render.

## Prerequisites

1. Create a Render account at [https://render.com](https://render.com)
2. Install Git and have it configured
3. Have your Groq API key ready

## Quick Deployment Steps

### 1. Push Your Code to GitHub

```bash
git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/yourusername/krr-app.git
git push -u origin main
```

### 2. Deploy to Render

1. Go to [https://render.com](https://render.com) and log in
2. Click "New +" and select "Web Service"
3. Select your GitHub repository
4. Configure the service:
   - **Name**: krr-backend
   **Runtime**: Python
   **Build Command**: `./build.sh`
   **Start Command**: `gunicorn app.main:app -w 4 -k uvicorn.workers.UvicornWorker --bind 0.0.0.0:$PORT`
   **Instance Type**: Free (or paid for better performance)

5. Click "Advanced Settings" and add these environment variables:
   ```
   ENVIRONMENT=production
   GROQ_API_KEY=your_groq_api_key_here
   ```

6. Click "Create Web Service"

### 3. Deploy Database

1. In the same Render dashboard, click "New +" and select "Private Service"
2. Select "PostgreSQL"
3. Configure:
   - **Name**: krr-db
   - **Region**: Same as your backend
   - **Plan**: Free (or Starter for paid)
   - **Database**: krr_db
   - **User**: krr_user
   - **Password**: Leave as auto-generated

4. Click "Create PostgreSQL Database"

### 4. Deploy Redis

1. Click "New +" and select "Private Service"
2. Select "Redis"
3. Configure:
   - **Name**: krr-redis
   - **Region**: Same as your backend
   - **Plan**: Free

4. Click "Create Redis Database"

### 5. Deploy Frontend

1. Click "New +" and select "Web Service"
2. Select your GitHub repository again
3. Configure the frontend service:
   - **Name**: krr-frontend
   - **Runtime**: Node
   - **Build Command**: `npm install && npm run build`
   - **Start Command**: `npm run preview`
   - **Instance Type**: Free

4. Click "Advanced Settings" and add environment variables:
   ```
   NODE_ENV=production
   VITE_API_URL=https://krr-backend.onrender.com
   VITE_API_BASE_URL=https://krr-backend.onrender.com
   ```

5. Click "Create Web Service"

### 6. Link Services

1. Go to your backend service settings
2. Under "Environment Variables", add:
   ```
   DATABASE_URL=postgresql://krr_user:password@krr-db:5432/krr_db
   REDIS_URL=redis://:password@krr-redis:6379
   CORS_ORIGINS=["https://krr-frontend.onrender.com"]
   ```

   Note: Replace `password` with the actual password from your database service.

2. Go to your frontend service settings
3. Update the CORS_ORIGINS in backend to include your frontend URL

## Environment Variables Setup

### Backend Required Variables

| Variable | Description | Example |
|----------|-------------|---------|
| `ENVIRONMENT` | Set to "production" | `production` |
| `GROQ_API_KEY` | Your Groq API key | `gsk_xxx` |
| `SECRET_KEY` | JWT secret (auto-generated by Render) | auto-generated |
| `DATABASE_URL` | PostgreSQL connection string | `postgresql://...` |
| `REDIS_URL` | Redis connection string | `redis://...` |
| `CORS_ORIGINS` | Frontend URLs | `["https://your-frontend-url.onrender.com"]` |

### Frontend Required Variables

| Variable | Description | Example |
|----------|-------------|---------|
| `NODE_ENV` | Set to "production" | `production` |
| `VITE_API_URL` | Backend API URL | `https://krr-backend.onrender.com` |
| `VITE_API_BASE_URL` | Backend API URL | `https://krr-backend.onrender.com` |

## Build and Deployment

### Build Script

The `build.sh` script handles:
- Installing Python dependencies
- Installing gunicorn for production
- Preparing the application for deployment

### Gunicorn Configuration

The backend uses Gunicorn with Uvicorn workers for production:
```bash
gunicorn app.main:app -w 4 -k uvicorn.workers.UvicornWorker --bind 0.0.0.0:$PORT
```

This provides:
- 4 worker processes
- Uvicorn worker class for ASGI support
- Binds to the port specified by Render

## Post-Deployment Steps

### 1. Create Admin User

After deployment, the backend will automatically create an admin user:
- Email: `admin@krr.com`
- Password: `admin123`

### 2. Test the Application

1. Open your frontend URL in browser
2. Log in with admin credentials
3. Try uploading a PDF
4. Test comparison and literature review features

### 3. Monitor Logs

Check service logs in the Render dashboard:
- Backend: `/api/library`, `/api/upload`, etc.
- Database: Connection and query logs
- Redis: Connection and cache logs

## Troubleshooting

### Common Issues

1. **Build Fails**
   - Check Python version (requires 3.10+)
   - Ensure all dependencies are in requirements.txt
   - Verify build.sh script is executable

2. **Import Errors**
   - Ensure all imports are relative (use `from app.module`)
   - Check for missing __init__.py files

3. **Database Connection Issues**
   - Verify DATABASE_URL format
   - Check database service is running
   - Ensure proper credentials

4. **CORS Issues**
   - Update CORS_ORIGINS with correct frontend URLs
   - Check for trailing slashes

### Debug Commands

To debug issues, you can SSH into your service:

```bash
# For backend
ssh render@krr-backend.onrender.com

# Check logs
tail -f logs/backend.log

# Check Python environment
python -c "import sys; print(sys.version)"
pip list
```

## Scaling Considerations

### Free Plan Limitations

- 512MB RAM
- Shared CPU
- Limited build time
- Services may sleep after 15 minutes of inactivity

### Paid Plan Benefits

- 1GB+ RAM
- Dedicated CPU
- Always-on services
- Faster builds
- Better performance

### Optimization Tips

1. **Use Redis for caching** - Already configured
2. **Implement proper shutdown** - Add graceful shutdown handlers
3. **Add monitoring** - Prometheus metrics endpoint available
4. **Use CDN** - For static assets

## Maintenance

### Regular Updates

1. Update dependencies regularly:
   ```bash
   pip-compile requirements.in
   npm audit fix
   ```

2. Monitor for security vulnerabilities
3. Update Render service when new versions are available

### Backup Strategy

- Database: Render provides automated backups
- Files: Uploads are stored locally, consider adding S3 integration
- Configuration: Keep environment variables backed up
